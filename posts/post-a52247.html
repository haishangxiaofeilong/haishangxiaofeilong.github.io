网络Java面试题

面试官问我什么是幂等，我说按钮变灰就行了，他直接跳过了这道题

2026-08-11 2465 字— 次阅读

先说结论：

幂等，就是同一个操作，执行一次和执行多次，对系统状态的影响完全相同。

它在支付系统里是条不能碰的生死线。

只要沾钱，系统就绝不能因为网络抖一下，让用户多扣一分。

很多人以为，幂等就是前端把支付按钮变灰、不让连点。

这是误解。

变灰只是表面防护，真正的幂等是：

允许用户重复点，甚至允许系统自动重试，后端依然只扣一次。

下面把这件事拆开讲透。

一、什么是幂等？电梯按钮就能讲明白

把它想成电梯的呼叫按钮。

你按一次，电梯来。

你心急连按十次，电梯也只来一次，不会派十部下来。

这就是幂等：

重复触发，结果不变。

软件里也是一样。

同一笔扣款请求，正常送达一次，和因为网络问题重发十次，系统最终只扣你一次。

二、为什么支付场景最容易重复？

原因在于网络超时。

手机点支付，请求顺着网络发往银行或支付平台。

网络突然卡一下，手机没收到支付成功的回执，就以为请求没成功。

这时候，不管是系统自动重试，还是你着急又点一遍，服务器都可能收到多条内容相同的扣款指令。

没有幂等，服务器就老老实实重复扣。

这就是为什么支付系统把幂等叫生死线。

三、幂等键：拦住重复扣款的闸门

堵这个漏洞，靠一个机制：

幂等键（Idempotency Key），说白了就是唯一流水号。

发起支付时，系统为这笔交易生成一个独一无二的流水号，和扣款请求绑在一起发往服务器。

服务器第一次见这个流水号，执行扣款，把结果记下来。

网络超时，第二条带着相同流水号的请求到了，服务器通过状态校验、唯一约束发现已经处理过，直接返回之前的结果，不再动余额。

核心逻辑看这段演示代码：

// 幂等键校验：唯一流水号 + 数据库唯一索引兜底
public PaymentResult pay(String idempotencyKey, PayRequest req) {
    // 1. 先查这个幂等键是否已处理过
    PaymentRecord record = recordMapper.selectByKey(idempotencyKey);
    if (record != null) {
        // 已处理：直接返回之前的结果，绝不重复扣款
        return record.getResult();
    }
    // 2. 没处理过：执行业务扣款
    PaymentResult result = doDeduct(req);
    // 3. 写入记录（唯一索引保证并发下也只进一条）
    recordMapper.insert(new PaymentRecord(idempotencyKey, result));
    return result;
}

关键就在唯一约束。

哪怕两条相同流水号的请求同时打进来，数据库唯一索引也保证只有一条能插入，另一条走「已处理」分支返回。

四、一个容易踩的边界：认流水号，不认商品

幂等防的是「同一笔业务被重复执行」，不干涉你真实的多次消费。

你在网上买两杯咖啡，分两次下单，系统生成两个完全不同的流水号。

服务器认出是两笔独立交易，正常扣两次。

幂等只认业务流水号，不认商品。

它精准拦截的是网络抖动和系统重试带来的幽灵重复，不是你的真实购买意愿。

五、前端禁点击 ≠ 后端幂等

不少人把「按钮变灰」当成幂等，这俩不是一回事。

一张表讲清：

对比维度 前端禁点击 后端幂等
防的是谁 用户手抖连点 网络超时 + 系统重试
生效范围 只管自己这台设备 跨请求、跨服务
按钮变灰失效时 重试机制照常发请求 照常只扣一次
本质 表面防护 兜底机制

按钮变灰只是第一层皮。

真兜底，在服务器。

六、哪些 HTTP 方法是幂等的？

面试官常顺着这个追问。

RFC 7231 （HTTP 协议规范）给的定义是这样的：

方法 是否幂等 说明
GET 是 读数据，不改变服务器状态
PUT 是 覆盖更新，重复执行结果一致
DELETE 是 删除一次和删多次，结果都是没了
POST 否 每次都新建资源，重复会多建

工程上，可安全重试的写操作多用 PUT，少用 POST。

很多支付网关的「重试接口」设计成幂等的 PUT，原因就在这。

回到面试：这道题怎么答

  • 幂等：同一操作执行多次，对系统状态的影响和执行一次完全相同。
  • 支付必做，根因是网络超时引发的重复请求。
  • 核心手段：幂等键 = 唯一流水号 + 状态校验 + 数据库唯一约束。
  • 边界：认流水号不认商品，两笔真下单照样扣两次。
  • 前端禁点击 ≠ 后端幂等，前者只是表面防护。
  • GET、PUT、DELETE 幂等，POST 不幂等（RFC 7231）。
