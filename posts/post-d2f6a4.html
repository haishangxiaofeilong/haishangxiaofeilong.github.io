LangChain大模型网络

你把工具都递给它了，可它凭什么知道下一步该干什么？

2026-09-18 2695 字— 次阅读

一个模型，能读会写，但它办不了事。

数据库里的数据，它读不到；你写的接口，它调不了。

你把工具递给它，它就能查数据、调接口了。

但下一步做什么，你没法提前写进代码。

工具一多，先用哪个、什么时候该停，这些都得现场判断。

这个决定权，是一次一次交给模型的。

它调一个工具，看一眼结果，再决定下一步。

一轮接一轮，直到这件事做完。

这样一套东西，就是 Agent 的骨架。

模型和工具中间，多出来一个循环

LangChain 里，Agent 是一套把模型和工具接起来的机制，靠的就是中间那个循环。

说白了：

让模型在一个循环里反复调工具，直到任务做完。

模型负责想和挑：

看一眼手上有什么信息，判断这一步要做什么，再挑一个工具，把参数填好。

LangChain 负责把工具真正跑起来，再把这次的结果返回给模型。

工具只管提供能力，用哪个、什么时候用，现场交给模型判断。

from langchain.agents import create_agent
from langchain.tools import tool

@tool
def query_order(order_id: str) -> str:
    """按订单号查状态。"""
    return f"{order_id}：已发货"

agent = create_agent(
    model=model,
    tools=[query_order],
    system_prompt="回答订单问题之前，先调工具拿数据。",
)

一次执行，链路长这样

需求先到模型。

模型看一眼上下文，判断要回答这个问题，得先拿到什么。

需要调工具，它就发出一条调用请求，落到工具集合里。

工具跑完，把结果返回给模型。

模型拿着结果，判断下一步该做什么。

不用再调工具，就直接给答案，这一轮结束。

还要调工具，就回到模型，再来一轮。

result = agent.invoke(
    {"messages": [{"role": "user", "content": "订单 20260918001 到哪了？"}]}
)
print(result["messages"][-1].content)

把这条链路拆细，是七步：

步骤 干什么
接住输入 用户的请求进到 Agent
模型推理 模型判断这一步要做什么
读取工具调用 从模型的输出里拿到工具名称和调用参数
把工具跑起来 LangChain 执行这一次调用
更新状态 把工具调用的结果和这一轮的记录写回上下文
判断下一步 有工具调用就继续执行，没有就结束
给出答案 把最终答案交给用户

这套循环的来历：ReAct

ReAct 这个名字来自 Reasoning 和 Acting 两个词，出在一篇 2022 年的论文里。

这套模式要做的事很朴素：

让模型在思考和行动之间来回切换。

LangChain 最早那批通用 Agent 就是照 ReAct 做的：

模型按固定格式写出下一步用哪个工具、参数填什么，LangChain 再从这段输出里解析出这次调用。

这套循环拆开是四个动作：

  • 思考：拿到问题，先判断下一步要做什么
  • 行动：从工具集合里挑一个，把参数填好
  • 观察：工具返回了什么，看一眼
  • 循环：把新信息带回思考那一步，重新判断

要调工具的时候，这四个动作转一圈，就是一轮。

换成示意代码是这样：

（注意方法名是编的，只用来表示循环）

while True:
    thought = model.think(question, history)   # 思考：判断下一步做什么
    tool_call = model.pick_tool(thought)       # 行动：挑工具、填参数
    if tool_call is None:
        return model.answer(thought)           # 不用再动手，直接给出答案
    result = run_tool(tool_call)               # 观察：把工具调用结果拿到手
    history.append(result)                     # 结果写回上下文，进入下一轮

跑循环的那层，换过一次实现

循环本身没变，但负责跑它的那一层，换过。

早期版本里，这个活由一个叫 AgentExecutor 的执行器干：

模型规划一步，执行器执行一步。

LangChain 1.0 之后，跑 Agent 的这套底子换了一遍，建在 LangGraph 上了。

模型、工具和状态都进到图里，连成一条能来回走的线，什么时候停下，看连线上的条件。

老项目要继续用原来那套，装 langchain-classic，再改一下导入路径就行。

不管哪一版，你在外面看到的都是一个循环。

什么时候该上 Agent

有的任务，步骤是固定的。

每一步用什么工具、按什么顺序走，你都清楚，那就直接写进代码，链路短、好排查。

另一种任务，下一步怎么做，要看上一步的结果才能决定。

比如第一次搜索没有结果，接下来是换个关键词再搜，还是转人工，得看到返回了什么才定得下来。

只有决定权必须留在模型手里的任务，才轮到 Agent 上场。
