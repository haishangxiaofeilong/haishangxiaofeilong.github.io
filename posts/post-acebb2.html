MySQL 聚簇索引和非聚簇索引：为什么二级索引查完还要回表？

2026-08-14 2436 字— 次阅读

MySQL 的索引底层是一棵 B+ 树，这个说法你应该听过。

但一张表往往建了好几个索引，每个索引都是一棵独立的 B+ 树。

那问题来了，每棵树的叶子节点，都存一份完整的行数据吗？

不是。

有的索引叶子节点里就是整行数据，有的索引里只放了指路信息。

这两种索引，一个叫聚簇索引，一个叫非聚簇索引。

数据只存一份

假设一张表占了 2 个 G，叶子节点里存的是完整的行记录。

这时候你再建一个索引，意味着又多出来一棵 B+ 树。

如果这棵树的叶子节点也存完整行记录，表的体积就变成 4 个 G。

再建一个，6 个 G。

每加一个索引，如果都复制一份完整数据，存储空间会快速膨胀，这显然不合理。

所以 InnoDB 定了一条规矩：

整张表的数据，只存一份。

其余的索引，叶子节点里不能存整行数据，得想个别的办法，把数据"指"回去。

这份数据，跟谁绑在一起存

数据落盘之前，InnoDB 得先选一个索引来组织整张表的数据，也就是定下来按哪个键来存。

InnoDB 选哪个键来组织数据，有固定的顺序，官网写得很清楚：

有主键，就跟着主键走。

没有主键，就跟着第一个非空的唯一索引走。

主键、唯一索引都没有，InnoDB 自己生成一个 6 字节的隐藏 row_id 来顶上。

这条规则写在 MySQL 官方文档里，白纸黑字。

而跟这份数据绑在一起存的那个索引，就叫聚簇索引。

聚簇索引：叶子节点就是整行数据

聚簇索引（clustered index）的特别之处，在于它的叶子节点直接放的是一整行记录。

数据记录就存在这棵 B+ 树的叶子节点里，按主键的顺序组织。

所以查主键的时候，顺着 B+ 树一路找到叶子节点，行数据就齐了，不用再跑第二趟。

因为整张表的数据只存一份，聚簇索引自然也只有一个。

你可以把它想成公司的员工档案原件。

全公司只有一份原件，按工号排好放在档案室里。

这份原件怎么存、存在哪，由工号（也就是主键）说了算。

非聚簇索引：叶子节点不存整行，要回表

除了聚簇索引，表里其他的 B+ 树索引都叫二级索引，也就是非聚簇索引。

它们的叶子节点里不放整行数据，放的是索引列的值和对应的聚簇索引键。

大多数表都有主键，聚簇索引键就是主键，所以也可以简单理解成：

叶子节点除了索引字段，还存了主键。

查非聚簇索引的时候，先在这棵树上找到对应的主键，再拿这个主键去聚簇索引里把整行捞出来。

后面这多走的一步，就是"回表"。

举个通俗的例子。

非聚簇索引像是书末尾的索引页，上面只写着"事务隔离级别——见第 128 页"。

页码就是主键。

你光看索引页拿不到内容，得翻到第 128 页，正文才是真东西。

-- name 上建了非聚簇索引 idx_name，主键是 id
SELECT * FROM user WHERE name = '张三';
-- 先走 idx_name 拿到 id，再回表去聚簇索引取整行

SELECT id, name FROM user WHERE name = '张三';
-- id 和 name 都在 idx_name 里，不用回表

一张表，两种索引摆一起看

维度 聚簇索引 非聚簇索引
叶子节点存什么 整行数据 索引键 + 主键（聚簇索引键）
数量 一张表只有一个 可以有多个
查数据要不要回表 不用，叶子即数据 要，拿到主键再去聚簇索引查
顺序 叶子节点按主键有序 叶子节点按索引键有序，与行数据的存储顺序无关
典型例子 主键索引 普通索引、二级唯一索引、联合索引

回表的代价，和不用回表的情况

回表意味着要再多走一趟聚簇索引、再做一次 B+ 树查找，查找成本更高。

如果相关数据页不在 Buffer Pool 里，还会带来额外的磁盘 IO。

查询走非聚簇索引、又要取索引之外的字段时，回表基本跑不掉。

也有不用回表的时候：

当要查的字段刚好全都已经在非聚簇索引里了，这棵索引自己就能把结果给全，不必再去找聚簇索引。这种情况叫覆盖索引。

还是上面那张 user 表，这次用 (name, age) 联合索引举例：

SELECT name, age FROM user WHERE name = '张三';
-- name、age 都在索引里，覆盖索引，不回表

所以建索引别贪多，关键在于让常用的查询尽量被覆盖。

理解了"数据只存一份"，回表为什么要发生、覆盖索引为什么能省掉它，就都说得通了。

面试时怎么答

如果面试官问聚簇索引和非聚簇索引的区别，按这三步说就行：

聚簇索引的叶子节点存整行数据，非聚簇索引的叶子节点只存索引键和主键、不存整行，这是最本质的区别。

因为数据只存一份，所以一张 InnoDB 表只能有一个聚簇索引；

它默认是主键，没有主键就退而求其次用第一个非空唯一键，都没有就由 InnoDB 用隐藏的 6 字节 row_id 顶上。

非聚簇索引查到的只是索引键和主键，要拿整行数据必须再回一次聚簇索引，这步就是回表。

想躲开回表，就让查询落在覆盖索引上。
